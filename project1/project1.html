Colorizing the Prokudin-Gorskii Photo Collection

Theo Dela Cruz

Overview

The goal of this project is to reconstruct color photographs from the Prokudin-Gorskii collection. Each glass plate collection contains 3 grayscales of the same scene, the three being red, green, and blue. They are captured through three separate filters, so they are a bit misaligned. The idea is that we form an algorithm to combine the three grayscales into one image, while taking into consideration the misalignment of the filters.

To create a color image, I separate the red, green, and blue grayscales. The blue channel is used as a reference for alignment, and the red and green channels are compared against it to find the best shift alignments for the red and green channels. The 3 images are then stacked on top of each other to create a cohesive RGB image.

I first created the naive implementation, in which I check a list of alignments for the entire image at once. This is good for the smaller images (for example the jpg file format), but can lead to performance issues on bigger images. I then created a multi-scale implementation, in which a larger image is repeatedly downsampled into lower resolutions, and shifts are calculated after each downsample.

Part 1: Single-Scale Alignment

Approach

To split the glass plate into the 3 color images, I took the approach of simply dividing the height into 3 equal parts, and assigning the colors to their respective places in the image. The original glass plate nicely divides the 3 grayscales into 3 equal parts.

The blue image is used as a reference for the red and green images. The correlation metric I chose to use was normalized cross-correlation (ncc). I used this metric to compare the blue and red images, as well as the blue and green images. I checked across many shifts to see which shift was the most aligned for both of the combinations.

To check across shifts, I used a double for loop. In both the x and y directions, I checked 15 pixels both ways. To clarify, this means that in the y direction I checked in the range of 15 pixels up and 15 pixels down (and 0, so 31 pixels total), and in the x direction 15 pixels left and 15 pixels right (and 0, so 31 pixels total). Each time, I would compute the ncc between the 2 images (either blue and green or blue and red), and keep track of which shift pairing (x and y shifts) gives the best correlation score.

To test each shift, I use np.roll tof align the image (red or green) along the corresponding x and y axes. Then, ncc is run between this shifted image and the blue reference image, and the score is tracked. np.roll does make an image wrap around, so some preprocessing has to be done in order for the correlation score to be more accurate (explained in next section).

Normalized Cross-Correlation

Normalized Cross-Correlation is performed by obtaining a demeaned image for the wanted image (red or green) and the reference image (blue). In an equation, this is image - np.mean(image). This gives you the variation between pixels rather than just the magnitudes of each pixel, which helps encode more consistent information across the three color images. You also have to obtain the normalized version of each image (obtain by dividing by the magnitude -> np.linalg.norm(image)) so that the pixel values are relative to each other.

We choose this method because larger NCC values generally indicate better alignment. A larger NCC value means that corresponding pixels in the same images similarly deviate from the mean of their respective images. Brighter red pixels will generally correspond with brighter blue and brighter green pixels, which the main idea behind utilizing the NCC (the same is true for darker pixels). When the 2 images are aligned, the brightness of most of the pixels will be aligned, which will grant the highest NCC score.

Before the score is calculated, the edges of the image are thrown out of the calculation. This is because np.roll wraps images around, so a pixel previously on the right side of the image could be on the left after a roll is performed. Therefore, we throw out the outer 10% on each side (both vertically and horizontally). This ensures that our calculation is only done on the pixels we actually want aligned, so there is a bigger focus on the actual image content.

Displacement Convention

The displacement beneath each image is in the form (x, y), for the green and red plates to align with the blue plate. Where x and y are the horizontal and vertical shifts that granted the best NCC score.

Part 2: Multi-Scale Image Pyramid

Motivation

On a larger image, single scale becomes inefficient since the displacement between the color images can be extremely large. This means you would have to search across a wider range of shifts, as well as calculate the NCC on a much larger image. This requires a lot of computation, and would be very slow and inefficient.

Utilizing an image pyramid makes this search much more efficient by finding the displacement on a smaller size of the image. This displacement can then be scaled back up to the original size image to obtain quite a good estimate for the total shift required. This means that you spend an initial computation to scale the image down, but you search a smaller window of shifts, which is computationally more efficient in the long run.

Building the Image Pyramid

To build the image pyramid, I recursively downsample the image (red or green) and the reference image (blue). The images continue to be reduced in size until they are small enough for the normal, single-scale search to be effective.

I downsampled each time by a factor of 0.8. Each time, I resized an image by 80% using skimage.transform.rescale with anti-aliasing enabled. This decreases the resolution at a fast enough rate to be computationally worth it, but slow enough so that the image structure is more maintained for the NCC score to find the correct alignment.

Coarse-to-Fine Alignment

Alignment begins at the smallest image in the pyramid. At this resolution (the coarsest), a naive search is performed to find the shift that produces the highest NCC score.

After finding this displacement, I divide by a factor of 0.8 (and round) in order to obtain the pixel displacement at the next resolution.

This displacement is then applied to the image at the next resolution using np.roll. Since the image is approximately aligned, the algorithm only needs to search a smaller window of shifts to account for the more accurate information that a higher resolution gives. The process is essentially making a guess, updating the information at the next stage, and refining the guess.

This process is repeated recursively as the algorithm gets through the pyramid (coarse to fine). At the end, the algorithm reaches the original image resolution and returns the full-scale alignment.

Failure Analysis

One image that had some issues was Emir.

Originally, I had a downsampling factor of 0.5, and this resulted in the red part of Emir being very separated from the green and blue channels. Switching to a 0.8 downsampling rate improved the results on all images, especially Emir, at the cost of performance. The issue with Emir is that the brightness is not necessarily uniform across the three colors. Our algorithm relies on a NCC metric, which favors similar brightness intensity patterns across the three color scales.

This produces a result that is generally good, but may be misaligned in some places. In fact, the exact issue I'm running into is the example listed on the website.

An improvement to make is to also consider a method that does not rely on brightness patterns. This could be something that creates a fingerprint out of an edge detector. Any method that does not consider the raw pixel values, but instead something that considers the image as a whole would be more effective at aligning Emir.
